# F2.16 - SIRET Mismatch Certification Validation

## Overview
This feature implements an automatic validation workflow when a training center attempts to attach an RNCP certification where the certificateur's SIRET (from France Compétences API) does not match the training center's SIRET. This ensures that only legitimate certifications are displayed on training center profiles.

## Business Logic

### SIRET Matching Process
When a training center attaches an RNCP certification:

1. **API Call**: System fetches certification details from Mission Apprentissage API
2. **SIRET Extraction**: 
   - Extracts `certificateurs_rncp` array from API response
   - Gets SIRET(s) of certificateur(s) authorized to deliver this certification
   - Gets training center's SIRET from their profile
3. **Comparison**:
   - **Match**: If center's SIRET is in the certificateurs list → Auto-approved (`approval_status = 'approved'`)
   - **Mismatch**: If center's SIRET is NOT in the list → Pending validation (`approval_status = 'pending'`)

### Automatic Actions on Mismatch

When SIRET mismatch is detected:
1. ✅ Certification is saved with `approval_status = 'pending'`
2. ✅ `siret_mismatch` flag is set to `true`
3. ✅ Both SIRETs are stored for audit trail
4. ✅ Email notification sent to **all admin users**
5. ✅ Badge count updated on admin sidebar
6. ✅ Certification appears in admin validation queue
7. ✅ Certification is **NOT visible** on center's public profile until approved

## API Endpoints

### 1. POST `/api/certifications/attach`
**Purpose**: Attach an RNCP certification to training center profile

**Authentication**: Required (Training Center user)

**Request Body**:
```json
{
  "rncpCode": "RNCP34826"
}
```

**Logic Flow**:
```typescript
1. Verify user is authenticated and has certificateur status
2. Fetch certification from Mission Apprentissage API
3. Extract certificateurs array with SIRETs
4. Compare center SIRET with certificateurs SIRETs
5. Set approval_status:
   - 'approved' if SIRET matches
   - 'pending' if SIRET mismatch
6. Store certification in database
7. If mismatch: Send email to all admins (async)
8. Return success response
```

**Response (SIRET Match)**:
```json
{
  "success": true,
  "certification": {
    "id": 123,
    "code": "RNCP34826",
    "title": "Manager opérationnel d'activités",
    "approvalStatus": "approved",
    "siretMismatch": false
  },
  "message": "Certification rattachée avec succès."
}
```

**Response (SIRET Mismatch)**:
```json
{
  "success": true,
  "certification": {
    "id": 123,
    "code": "RNCP34826",
    "title": "Manager opérationnel d'activités",
    "approvalStatus": "pending",
    "siretMismatch": true
  },
  "message": "Certification rattachée avec succès. Elle est en attente d'approbation en raison d'une non-concordance du SIRET."
}
```

**Key Code Section**:
```typescript
// Extract certificateurs information
const certificateurs = cert.type?.certificateurs_rncp || [];
const certificateurSiret = certificateurs.length > 0 ? certificateurs[0].siret : null;
const certificateurName = certificateurs.length > 0 ? certificateurs[0].nom : null;

// Check for SIRET mismatch
const centerSiret = trainingCenter.siret;
let siretMismatch = false;
let approvalStatus = 'approved';

if (certificateurSiret && centerSiret) {
  const certSirets = certificateurs.map((c: any) => c.siret);
  siretMismatch = !certSirets.includes(centerSiret);
  
  if (siretMismatch) {
    approvalStatus = 'pending';
    approvalRequestedAt = new Date();
  }
}

// Send email notification to admins if SIRET mismatch
if (siretMismatch && certificateurName && certificateurSiret) {
  sendCertificationValidationEmail({
    centerName: trainingCenter.name,
    certificationTitle: title,
    certificationCode: rncpCode,
    centerSiret: centerSiret || 'Non renseigné',
    certificateurName,
    certificateurSiret,
  });
}
```

### 4. PATCH `/api/admin/certifications/[id]`
**Purpose**: Approve or reject a pending certification

**Authentication**: Required (Admin user)

**Request Body**:
```json
{
  "approvalStatus": "approved",  // or "rejected"
  "approvalComment": "Certification validée après vérification"  // MANDATORY for rejection (min 10 chars)
}
```

**Validation Rules**:
- `approvalStatus` must be either "approved" or "rejected"
- **For rejections**: `approvalComment` is **MANDATORY** and must be at least **10 characters**
- For approvals: `approvalComment` is optional

**Logic**:
```typescript
1. Verify admin authentication
2. Validate approval status ('approved' or 'rejected')
3. If rejection: Validate comment exists and >= 10 characters
4. Fetch certification with training center details
5. Update certification record:
   - Set approval_status
   - Set approved_at timestamp
   - Set approved_by (admin user ID)
   - Set approval_comment (mandatory for rejection)
6. Send email notification to training center
7. Return success response
```

**Response**:
```json
{
  "success": true,
  "message": "Certification approuvée avec succès",
  "certification": {
    "id": 123,
    "approvalStatus": "approved",
    "approvedAt": "2025-10-10T15:30:00Z",
    "approvedBy": 1
  }
}
```

### 5. GET `/api/admin/pending-jury-count`
**Purpose**: Get total count of pending validation tasks for admin badge

**Authentication**: Required (Admin user)

**Response**:
```json
{
  "count": 5,                    // Total (profiles + certifications)
  "profiles": 3,                 // Pending jury profiles
  "certifications": 2            // Pending certifications
}
```

**Logic**:
```typescript
// Count pending jury profiles
const pendingJuryCount = await db
  .select({ count: users.id })
  .from(users)
  .where(
    and(
      eq(users.validationStatus, 'pending'),
      eq(users.profileCompleted, true),
      eq(users.userType, 'jury')
    )
  );

// Count pending certifications
const pendingCertifications = await db
  .select({ count: franceCompetenceCertifications.id })
  .from(franceCompetenceCertifications)
  .where(eq(franceCompetenceCertifications.approvalStatus, 'pending'));

// Return total
const totalCount = pendingJuryCount.length + pendingCertifications.length;
```

## Testing Scenarios

### Scenario 1: SIRET Match (Auto-Approval)
1. Training center with SIRET "12345678901234"
2. Attaches RNCP certification
3. API returns certificateur with same SIRET
4. **Result**: `approval_status = 'approved'`, no email sent
5. Certification immediately visible on profile

### Scenario 2: SIRET Mismatch (Manual Validation)
1. Training center with SIRET "98765432109876"
2. Attaches RNCP certification
3. API returns certificateur with different SIRET "12345678901234"
4. **Result**: 
   - `approval_status = 'pending'`
   - `siret_mismatch = true`
   - Email sent to all admins
   - Badge count incremented
5. Certification NOT visible on profile
6. Appears in admin validation queue

### Scenario 3: Admin Approval
1. Admin receives email notification
2. Clicks "Valider la certification" button
3. Reviews SIRET information
4. Clicks approve button
5. Adds optional comment
6. **Result**:
   - `approval_status = 'approved'`
   - `approved_at` timestamp set
   - `approved_by` set to admin ID
   - Certification now visible on center profile
   - Removed from validation queue

### Scenario 4: Admin Rejection
1. Admin reviews certification
2. Determines it's not legitimate
3. Clicks reject button
4. **MUST enter rejection reason** (minimum 10 characters)
   - Button is disabled until valid comment is entered
   - Real-time character count shown
   - Validation feedback displayed
5. Confirms rejection
6. **Result**:
   - `approval_status = 'rejected'`
   - `approval_comment` stored in database (min 10 chars)
   - Email sent to training center with rejection reason
   - Certification remains hidden
   - Center can see rejection status
   - Can contact support if needed
