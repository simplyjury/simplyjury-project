# F2.16 Enhancement - Training Center Approval Status Display

## Overview
This enhancement updates the training center's certification page (`/dashboard/center/certifications`) to properly display the approval status of SIRET mismatch certifications after admin decisions.

**Implementation Date**: 2025-10-10

## What Was Implemented

### 1. API Enhancement

**File**: `/app/api/certifications/route.ts`

**Changes**:
- Added `approval_comment` field to the certification data returned by GET endpoint
- This allows training centers to see admin's rejection reason

### 2. Interface Updates

**Files**: 
- `/app/dashboard/center/certifications/page.tsx`
- `/components/certifications/certification-card.tsx`

**Changes**:
- Added `approval_comment?: string` to `CertificationData` interface
- Added `onResubmit?: (id: number) => void` callback prop

### 3. UI Components - CertificationCard

**File**: `/components/certifications/certification-card.tsx`

#### Approved Status (approval_status = 'approved')
- ✅ **Pending banner removed** - No yellow warning box displayed
- ✅ **Pending badge removed** - No "En attente" badge next to title
- ✅ **Normal actions displayed** - Shows "Trouver des jurys", "Statistiques", "Gérer" buttons
- ✅ **Certification fully visible** - Functions as a normal active certification

#### Pending Status (approval_status = 'pending')
- 🟡 **Yellow warning banner** - Displays "En attente d'approbation"
- 🟡 **Yellow badge** - Shows "En attente" next to title
- 🟡 **SIRET mismatch message** - If applicable
- ✅ **Normal actions displayed** - All action buttons available

#### Rejected Status (approval_status = 'rejected')
- 🔴 **Red rejection banner** - Displays "Certification non approuvée"
- 🔴 **Red badge** - Shows "Rejetée" next to title
- 🔴 **SIRET mismatch explanation** - Shows why it was flagged
- 🔴 **Admin comment display** - Shows rejection reason in highlighted box
- 🔴 **Resubmit button only** - Replaces all action buttons with "Redemander la validation"

## Technical Implementation

### State Management
- No real-time updates required
- Training center must refresh page to see status change
- Uses existing SWR data fetching pattern

### Data Flow
```
Admin approves/rejects on /dashboard/admin/validation-profils
    ↓
PATCH /api/admin/certifications/[id]
    ↓
Database: approval_status updated to 'approved' or 'rejected'
    ↓
Email sent to training center
    ↓
Training center refreshes /dashboard/center/certifications
    ↓
GET /api/certifications (includes approval_comment)
    ↓
CertificationCard renders appropriate UI based on approval_status
```

### Conditional Rendering Logic

```typescript
// In CertificationCard component

// 1. Banner display
{certification.approval_status === 'pending' && <PendingBanner />}
{certification.approval_status === 'rejected' && <RejectedBanner />}
// No banner for 'approved'

// 2. Badge display
{certification.approval_status === 'pending' && <PendingBadge />}
{certification.approval_status === 'rejected' && <RejectedBadge />}
// No badge for 'approved'

// 3. Action buttons
{certification.approval_status === 'rejected' ? (
  <ResubmitButton />
) : (
  <NormalActionButtons />
)}
```
