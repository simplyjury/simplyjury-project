# F5.7 - Dashboard Centre - Implémentation

## Vue d'ensemble

Implémentation du tableau de bord pour les centres de formation avec des données réelles. Le dashboard affiche les statistiques personnalisées et l'activité du centre connecté, avec une approche mobile-first.

## Fonctionnalités implémentées

### 1. API Endpoint - Statistiques Centre
**Fichier**: `/app/api/center/stats/route.ts`

#### Authentification et sécurité
- Vérification du token JWT via `AuthService.verifyToken()`
- Contrôle d'accès : seuls les utilisateurs avec `userType = 'centre'` peuvent accéder
- Utilisation du contexte RLS (Row Level Security) avec `withRLSContext()`
- Utilisation du client Supabase avec service role key pour les requêtes

#### Données récupérées
```typescript
interface CenterStats {
  totalRequests: number;        // Nombre total de demandes envoyées
  pendingRequests: number;      // Demandes en attente de réponse du jury
  acceptedRequests: number;     // Demandes acceptées par les jurys
  completedSessions: number;    // Sessions terminées
  contactedJuries: number;      // Nombre de jurys contactés (unique)
  activeConversations: number;  // Conversations actives
  averageRatingGiven: number;   // Note moyenne donnée aux jurys (arrondie à 1 décimale)
  totalRatingsGiven: number;    // Nombre total d'évaluations données
}
```

#### Requêtes Supabase utilisées
1. **Demandes totales**: `COUNT(*) FROM jury_requests WHERE training_center_id = centerId`
2. **Demandes en attente**: `COUNT(*) FROM jury_requests WHERE training_center_id = centerId AND status = 'pending'`
3. **Demandes acceptées**: `COUNT(*) FROM jury_requests WHERE training_center_id = centerId AND status = 'accepted'`
4. **Sessions terminées**: `COUNT(*) FROM jury_requests WHERE training_center_id = centerId AND status = 'completed'`
5. **Jurys contactés**: `COUNT(DISTINCT jury_id) FROM conversations WHERE training_center_id = centerId`
6. **Conversations actives**: `COUNT(*) FROM conversations WHERE training_center_id = centerId AND status = 'active'`
7. **Note moyenne donnée**: `AVG(overall_rating) FROM session_ratings JOIN jury_requests WHERE rater_type = 'centre' AND status = 'active'`

### 2. API Endpoint - Demandes récentes
**Fichier**: `/app/api/center/recent-requests/route.ts`

#### Fonctionnalité
- Affiche les 3 demandes les plus récentes envoyées par le centre
- Filtre les demandes envoyées dans les 10 derniers jours
- Tri par date de création décroissante
- Inclut les informations du jury contacté

#### Données affichées
- **Nom de la certification**: `certification_title` ou `certification_code`
- **Code de certification**: `certification_code` (si disponible)
- **Nom du jury**: Prénom + Nom du jury ou nom d'utilisateur
- **Date d'envoi**: Format français (ex: "30 sept. 2025")
- **Nombre de candidats**: Avec pluralisation automatique
- **Statut**: Badge coloré (En attente, Acceptée, Refusée, Terminée)
- **Modalité**: Présentiel, Visio, ou Hybride

#### Requête Supabase
```typescript
supabase
  .from('jury_requests')
  .select(`
    id, status, certification_title, certification_code,
    session_date, candidate_count, modality, created_at,
    users!jury_requests_jury_id_fkey(name),
    jury_profiles!inner(first_name, last_name)
  `)
  .eq('training_center_id', centerId)
  .gte('created_at', tenDaysAgo.toISOString())
  .order('created_at', { ascending: false })
  .limit(3)
```

### 3. Composant Dashboard Centre
**Fichier**: `/components/dashboard/center-dashboard.tsx`

#### Intégration des données réelles

#### KPIs implémentés

##### Demandes envoyées
- **Valeur**: Nombre total de demandes envoyées par le centre
- **Tendance**: `"${totalRequests} au total"`
- **Icône**: Send
- **Couleur**: Bleu par défaut (`text-[#0d4a70]`)

##### En attente
- **Valeur**: Nombre de demandes avec status = 'pending'
- **Tendance**: 
  - Si > 0: `"En attente de réponse"`
  - Si = 0: `"Aucune demande en attente"`
- **Icône**: Clock
- **Couleur**: Orange (`text-orange-600`)

##### Sessions réalisées
- **Valeur**: Nombre de demandes avec status = 'completed'
- **Tendance**: `"${count} session(s) terminée(s)"`
- **Icône**: CheckCircle
- **Couleur**: Vert (`text-green-600`)

##### Jurys contactés
- **Valeur**: Nombre unique de jurys contactés via conversations
- **Tendance**: `"${activeConversations} conversation(s) active(s)"`
- **Icône**: Users
- **Couleur**: Violet (`text-purple-600`)

## Structure des données

### Tables utilisées
1. **training_centers**: Profil du centre de formation
   - `id`: ID du centre
   - `user_id`: ID de l'utilisateur associé
   - `name`: Nom du centre
   
2. **jury_requests**: Demandes envoyées aux jurys
   - `training_center_id`: ID du centre émetteur
   - `jury_id`: ID du jury destinataire
   - `status`: Statut de la demande (pending, accepted, declined, completed)
   - `certification_title`: Titre de la certification
   - `certification_code`: Code de la certification
   - `candidate_count`: Nombre de candidats
   - `modality`: Modalité (presentiel, visio, hybride)
   
3. **conversations**: Conversations avec les jurys
   - `training_center_id`: ID du centre
   - `jury_id`: ID du jury
   - `status`: Statut de la conversation (active, closed)

4. **session_ratings**: Évaluations données aux jurys
   - `rater_type`: Type d'évaluateur ('centre' ou 'jury')
   - `overall_rating`: Note globale
   - `status`: Statut de l'évaluation (active, hidden, etc.)

5. **users**: Informations utilisateur
   - `id`: ID de l'utilisateur
   - `name`: Nom de l'utilisateur
   - `user_type`: Type d'utilisateur (centre, jury, admin)

6. **jury_profiles**: Profils des jurys
   - `user_id`: ID de l'utilisateur jury
   - `first_name`: Prénom du jury
   - `last_name`: Nom du jury

## Sécurité

### Authentification
- Vérification obligatoire du token JWT via `AuthService.verifyToken(request)`
- Contrôle du type d'utilisateur (centre uniquement)
- Retour d'erreur 401 si non authentifié
- Retour d'erreur 403 si mauvais type d'utilisateur

### Row Level Security (RLS)
- Utilisation de `withRLSContext(user.id)` pour toutes les requêtes
- Garantit que chaque centre ne voit que ses propres données
- Isolation complète des données entre centres

### Validation des données
- Vérification de l'existence du centre avant traitement
- Gestion des valeurs nulles dans les calculs de moyenne
- Filtrage des évaluations (status = 'active')
- Utilisation de Supabase service role key pour contourner RLS au niveau API

- **Icons**: Lucide React

### Pattern de requêtes
```typescript
// 1. Authentification
const authResult = await AuthService.verifyToken(request);

  // Requêtes Supabase ici

// 4. Retour formaté

```
