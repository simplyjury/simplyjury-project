# F5.7 - Dashboard Jury - Implémentation

## Vue d'ensemble

Implémentation du tableau de bord pour les jurys avec des données réelles remplaçant les données mockées. Le dashboard affiche les statistiques personnalisées et l'activité du jury connecté.

## Fonctionnalités implémentées

### 1. API Endpoint - Statistiques Jury
**Fichier**: `/app/api/jury/stats/route.ts`

#### Authentification et sécurité
- Vérification du token JWT via `AuthService.verifyToken()`
- Contrôle d'accès : seuls les utilisateurs avec `userType = 'jury'` peuvent accéder
- Utilisation du contexte RLS (Row Level Security) avec `withRLSContext()`

#### Données récupérées
```typescript
interface JuryStats {
  totalRequests: number;      // Nombre total de demandes reçues
  pendingRequests: number;    // Demandes en attente de réponse
  completedMissions: number;  // Missions terminées
  averageRating: number;      // Note moyenne (arrondie à 1 décimale)
  totalRatings: number;       // Nombre total d'évaluations reçues
}
```

#### Requêtes SQL utilisées
1. **Demandes totales**: `COUNT(*) FROM jury_requests WHERE jury_id = user.id`
2. **Demandes en attente**: `COUNT(*) FROM jury_requests WHERE jury_id = user.id AND status = 'pending'`
3. **Missions terminées**: `COUNT(*) FROM jury_requests WHERE jury_id = user.id AND status = 'completed'`
4. **Note moyenne**: `AVG(overall_rating) FROM session_ratings WHERE rated_id = user.id AND status = 'active' AND is_visible = true`

### 2. Composant Dashboard Jury
**Fichier**: `/components/dashboard/jury-dashboard.tsx`

#### Intégration des données réelles
- Remplacement de `useSWR(null, fetcher)` par `useSWR('/api/jury/stats', fetcher)`
- Ajout d'états de chargement et de gestion d'erreurs
- Affichage dynamique des tendances basées sur les données réelles

#### KPIs implémentés

##### Demandes reçues
- **Valeur**: Nombre total de demandes reçues par le jury
- **Tendance**: `"${totalRequests} au total"`
- **Icône**: FileText
- **Couleur**: Bleu par défaut

##### En attente
- **Valeur**: Nombre de demandes avec status = 'pending'
- **Tendance**: 
  - Si > 0: `"Nécessite une réponse"`
  - Si = 0: `"Aucune demande en attente"`
- **Icône**: Clock
- **Couleur**: Orange (`text-orange-600`)

##### Missions réalisées
- **Valeur**: Nombre de demandes avec status = 'completed'
- **Tendance**: `"${count} mission(s) terminée(s)"`
- **Icône**: CheckCircle
- **Couleur**: Vert (`text-green-600`)

##### Note moyenne
- **Valeur**: 
  - Si > 0: `"${rating}/5"`
  - Si = 0: `"-"`
- **Tendance**: 
  - Si > 0: `"Basée sur ${totalRatings} évaluation(s)"`
  - Si = 0: `"Aucune évaluation"`
- **Icône**: Star
- **Couleur**: Jaune (`text-yellow-600`)

## Structure des données

### Tables utilisées
1. **jury_requests**: Demandes de missions
   - `jury_id`: ID du jury
   - `status`: Statut de la demande (pending, accepted, declined, completed)
   
2. **session_ratings**: Évaluations des jurys
   - `rated_id`: ID du jury évalué
   - `overall_rating`: Note globale
   - `status`: Statut de l'évaluation (active, hidden, etc.)
   - `is_visible`: Visibilité publique

### 4. Section Demandes récentes
**Fichier**: `/app/api/jury/recent-requests/route.ts`

#### Fonctionnalité
- Affiche les 3 demandes les plus récentes reçues par le jury
- Filtre les demandes reçues dans les 10 derniers jours
- Tri par date de création décroissante

#### Données affichées
- **Nom de la certification**: `certification_title` ou `certification_code`
- **Code de certification**: `certification_code` (si disponible)
- **Centre de formation**: Nom du centre demandeur
- **Date de réception**: Format français (ex: "30 sept. 2025")
- **Nombre de candidats**: Avec pluralisation automatique
- **Statut**: Badge coloré (En attente, Acceptée, Refusée, Terminée)
- **Modalité**: Présentiel, Visio, ou Hybride

#### Requête SQL
```sql
SELECT id, status, certification_title, certification_code, 
       session_date, candidate_count, modality, created_at,
       training_centers(name, contact_person_name)
FROM jury_requests 
WHERE jury_id = user.id 
  AND created_at >= NOW() - INTERVAL '10 days'
ORDER BY created_at DESC 
LIMIT 3
```

#### États de l'interface
- **Chargement**: Message "Chargement des demandes..."
- **Aucune demande**: "Les demandes reçues dans les 10 derniers jours apparaîtront ici"
- **Avec données**: Liste des 3 demandes récentes + bouton "Voir toutes les demandes"
